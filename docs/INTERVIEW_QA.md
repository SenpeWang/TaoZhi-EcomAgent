# 企业多智能体项目架构说明

## 为什么拆分入库和问答？

资料入库完成格式解析、切片、来源登记、索引及发布审批，问答只检索已发布授权资料。避免每次问题重新解析资料，也避免上传未确认草稿被直接用于回答。

## 角色和组织权限如何组合？

资料先属于公司、部门、小组或指定人员，再有员工、组长、老板密级。角色绑定任职范围。企业 ID 从会话读取，所有读取与写入经过同一个权限模块；先选择授权候选再排序，模型不能提高权限。

## 管理员为什么不能默认读取机密？

系统运维和业务授权分离。管理员能维护组织、账号、配置与系统审计；业务机密须负责人审批单独授权。不能自己给自己增加业务权，也不能未经老板批准恢复受保护老板账号。

## 多智能体怎样协作？

LangGraph 依次执行计划、授权检索、按需专家、证据核验和发布。规格、适配、售后、运营、供应链、经营分析按问题路由，最多三类专家。模型输出须匹配授权原文和数字，实际回答保留可核验出处；没有证据时明确缺口。

## 为什么审核仍然重新校验提问人？

审核只决定是否允许发布，不改变提问人的权限。组长或老板看到的机密不能因审核进入员工答案。发布、引用、历史和个人追问都会验证提问人当前权限、文档与 ACL 版本。

## 任务中断如何处理？

PostgreSQL 队列通过行锁、租约、心跳和执行版本控制归属。独立 Worker 由 Supervisor 自动重启；过期任务有限重试，模型预算跨重试累积。LangGraph 检查点持久化，但恢复不会无条件复用旧授权上下文，会重新校验和检索。

## 如何避免演示数据被当作真实业务？

演示与正式数据库、会话和原件目录隔离；旧演示商品资料标注来源。未接真实接口显示未接入，只读业务响应必须符合企业、组织、负责人、时效与字段规则。退款、改价与订单修改没有自动执行路径。

## 哪些能力还需要真实部署验收？

真实 OMS/ERP 数据、企业 SSO、多机高可用、异机备份和复杂扫描文档解析。当前验证的是单机工作台、权限闭环、队列恢复、模型调用与迁移恢复，不能代替实际企业数据上的业务验收。
