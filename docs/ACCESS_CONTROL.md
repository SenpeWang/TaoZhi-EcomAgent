# 企业权限与文档治理

## 身份与组织

组织结构为公司、部门、小组、成员。默认建立商品产品、电商运营、客服售后、采购供应链、财务综合五个部门和十个小组。任职记录绑定组织，支持多组任职；新增、移除或改变任职需要业务负责人审批。

管理员维护系统配置、人员和组织，不自动成为业务负责人。员工默认只读并查看本人任务。组长维护和审核负责范围的业务。老板对公司业务有读写权限，批准任命组长、老板身份、机密授权、扩大共享、密级调整和受保护账号变更。管理员不能批准自己的业务权限提升。最后一个有效老板或管理员不能被删除、停用或降权。

## 资料决策

每份资料记录员工级、组长级或老板级，以及公司共享、所属组织或仅指定人员范围。组织符合且密级足够才开放；本组组长不能直接阅读其他小组内部资料。公司普通员工任职不等于所有下级团队的成员身份。

单文档授权只影响该资料，可设置读取、下载和到期时间。单文档例外不授予编辑能力，员工仍只读；禁止授权优先于允许授权；过期授权每次请求重新校验。管理员可以按老板提供的资料编号维护授权配置，但不会因此获取标题、正文或检索命中。所有增加权限的申请须经对应负责人批准。

新资料先在受限草稿中解析、切片、登记来源、建索引，再经负责人确认范围和密级后发布。组长仅可发布本范围内最高组长级的资料。历史版本保留当时策略，当前阅读授权与历史策略共同决定可见性，不能利用新授权读取旧机密版本。

## 全链路限制

统一模块 `enterprise/policy.py` 覆盖 API、检索、Agent 工具、独立 Worker、审核、引用、历史答案和记忆。请求和模型不能提供有效角色或企业身份；服务端从会话加载当前账号和任职。

搜索先选授权候选，再做 BM25 与本地向量排序；不返回隐藏资料的标题、片段或命中数量。原文和附件置于私有目录，没有公开文件 URL。读取和下载分别授权。非老板读取、模型输入和附件下载过滤电话、详细地址、身份证及凭据；采购成本仅向老板业务查询开放。上传含复杂表格、图片或扫描正文时需人工核对，当前解析不提供 OCR。

权限撤销、授权到期、调岗、离职、密级提高、版本变更和资料删除会影响后续访问。源版本和 ACL 版本不再一致时历史答案隐藏，要求重新查询；不复用跨用户答案缓存。个人追问记忆重读当前获准来源，未知来源的旧内容不进入问答。

审核通过不把审核人的权限授予提问人。任务完成前不发送正文和证据，阶段流仅有中文进度。发布前再次检查提问人、来源、当前执行版本和取消状态；崩溃恢复重新检索并重新校验权限。资料不足、引用冲突和接口断连不会因人工审核而变成可信事实。

老板级资料默认禁止外部模型处理。老板须批准资料 AI 许可；提问还须显式允许外部 AI。获准单文档阅读的员工不会取得老板角色；老板级来源不会因此自动传给外部模型。未允许 AI 时提供授权原文摘录。

## 登录、审计与运行边界

同源 HttpOnly 会话 Cookie 默认两小时，写请求要求 CSRF；停用、调岗、改密和权限身份变更会撤销旧会话。演示与正式 Cookie 名称不同。正式环境拒绝演示口令，老板初始化由部署账号私有工具完成。

审计只存账号或资源编号、组织、级别、动作及经过白名单限制的元信息，不存密码、API Key、机密正文或完整客户数据。管理员查看系统审计，业务负责人查看符合组织与密级的业务审计。

目前采用用户目录 PostgreSQL 和单机监督进程。部署账号具备数据库与文件运维能力，应用权限不能限制拥有服务器账号的运维人员；需结合企业主机账号制度。若改为公网访问，必须通过 HTTPS 并设置 `V3_COOKIE_SECURE=true`。
