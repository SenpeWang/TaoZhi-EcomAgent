# 场景级质量、决策门控与验收需求

本手册把「场景级评测、发版门禁、证据与门控、验收举证」类岗位要求，收敛为本仓库可执行、可验收的需求条目。评测口径与指标定义仍以 [基准与门禁](../../evals/BENCHMARK.md) 为唯一来源；本手册只回答三件事：**评测什么、门禁在哪一层拦住、证据如何举证**。

需求条目逐条标注实现状态：`已实现`（代码/命令可直接核对）、`部分实现`（有能力但不成体系）、`需求`（尚未实现，作为后续验收依据）。

## 1. 范围与责任边界

| 项 | 说明 |
| --- | --- |
| 覆盖范围 | 场景级评测集与 Golden Case、发版质量门禁、证据包与停止条件、决策门控（降级/拦截/转人工）、评测与门控接入 CI 与发布、决策轨迹与验收材料、缺陷与版本质量报告、在线效果口径、记忆与经验治理 |
| 不覆盖 | 模型选型与价格谈判、业务系统内部实现、客户合同条款；具体指标计算口径以 `evals/BENCHMARK.md` 为准 |
| 责任边界 | 本手册是需求与验收依据；实现状态以代码为准，文档不把未实现能力写成现状 |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 场景级评测集 | 按业务场景组织、带期望行为与判定规则的用例集合，随版本进 Git |
| Golden Case | 被冻结、作为回归基准的关键用例；变更须评估可比性 |
| 证据包 | 一次结论所依赖的数据版本、模型/算法版本、约束与规则结果、引用证据、停止原因与人工确认记录 |
| 停止条件 | 系统主动终止或转交的显式原因（完成、取消、超时、轮次上限、证据不足等） |
| 决策门控 | 在输出前执行的判定：超适用域降级、证据缺失拦截、风险分级转人工 |
| 决策轨迹 | 可回放的执行记录（任务、步骤、模型与工具调用、门控结论、Trace ID） |
| 算法版本 | 代码提交 + 模型标识 + 检索参数 + Prompt 源摘要 + 判定器摘要构成的不可变快照 |
| 回标 | 用新证据或人工确认重新标注历史经验条目，只追加、不改写历史 |
| 晋级 | 经验/技能条目从草稿到生效的状态迁移，需样本量与人工确认双条件 |
| 采纳率 / 根因正确率 | 在线效果类指标，判定规则见第 9 节 |

## 5. 需求条目

### 5.1 Q1 场景级评测集与发版门禁

- **Q1-R1**：每个业务场景至少有一组可回归用例，包含期望行为、判定规则与数据来源；用例集随版本进 Git，内容变更必须升数据集版本号。
- **Q1-R2**：发版门禁分三层——CI 必过（仓库边界、语法、前端构建、离线回归、合成回放）、发布前必过（在线场景评测/分层评测）、发布后观察（在线效果指标）；任一层未过不得发布。
- **Q1-R3**：每个评测批次必须绑定数据集版本、算法版本与基线批次；不可比批次（版本或口径不同）不得作为放行依据。
- **验收**：`make evals-center-check` 通过；批次详情可见数据集版本/算法版本/基线标记；发布记录引用批次编号。
- **状态**：R1、R3 已实现；R2 的在线层靠受控评测任务执行与人工确认，举证模板为 P1 需求。

### 5.2 Q2 证据包与停止条件

- **Q2-R1**：结论必须带证据包，字段固定：`dataset_version`、`algorithm_version`、`git_sha`、`mode`、`scope`、`stop_reason`、`rule_results`、`citations`、`human_confirmations`、`trace_id`、`run_id`。
- **Q2-R2**：证据不足必须返回明确的缺口说明与补证路径，不允许以空结果或猜测替代。
- **Q2-R3**：停止条件必须显式记录原因（`completed`/`cancelled`/`timeout`/`max_turns`/证据不足/越权拦截），不得以静默结束代替。
- **验收**：运行轨迹可查到上述字段；抽查结论与引用一致；`make test` 中引用与缺口相关用例通过。
- **状态**：停止原因与核验已实现；证据包统一导出为 P1 需求。

### 5.3 Q3 决策门控

- **Q3-R1 超适用域降级**：问题超出资料适用域时先降级（限定范围、标注不确定、给出所需凭据），不得强行给出确定结论。
- **Q3-R2 证据缺失拦截**：无授权证据或证据不足时拦截结论，输出缺口与补证方向。
- **Q3-R3 风险分级转人工**：涉及高等级权限、越权工具、关键业务结论时进入审核并留痕；审核结论可追溯。
- **验收**：样例问题中越界类必须降级/拦截；高风险动作出现在审核队列；轨迹包含门控结论与处理人。
- **状态**：领域规则与审核流程已实现；门控结论统一字段与风险等级口径为 P1 需求。

### 5.4 Q4 接入 CI 与发布流程

- **Q4-R1**：CI 只跑确定性与离线门禁（当前为仓库边界、Python 语法、前端构建、离线回归、合成轨迹回放）。
- **Q4-R2**：在线场景评测必须通过受控评测任务（`POST /api/evaluations/runs/trigger`）执行，结果入库后才可作为发布依据；执行失败与门禁失败分别记录。
- **Q4-R3**：推送前本地跑第 1–4 类快检，权威判定以 GitHub CI 为准；禁止跳过钩子、强推或删测试。
- **验收**：CI 四个 job 全绿；评测任务状态可查（`GET /api/evaluations/jobs/{job_id}`）；发布记录关联批次。
- **状态**：已实现。

### 5.5 Q5 可审计决策轨迹与验收报告

- **Q5-R1**：验收报告必须由评测批次、证据包与审计记录生成，禁止手工填写指标数字。
- **Q5-R2**：报告需含批次编号、数据集/算法版本、门禁结论、失败用例清单、不可比声明与证据摘要（SHA-256）。
- **Q5-R3**：报告与原始评测报告一并留档，支持按 SHA-256 校验。
- **验收**：报告字段可回溯到库表与对象存储；抽样校验 SHA 一致。
- **状态**：轨迹/报告/审计已实现；报告模板与导出为 P1 需求。

### 5.6 Q6 测试设计、回归、缺陷与现场复现

- **Q6-R1**：用例需覆盖数据类异常：口径对齐、字段缺失、时钟/时区异常、权限/授权变更。
- **Q6-R2**：缺陷登记应包含编号、关联用例、数据集/算法版本、根因分类、修复批次与闭环状态（P1 需求）。
- **Q6-R3**：版本质量报告按发布版本汇总门禁结论、失败用例、缺陷统计与趋势（P1 需求）。
- **Q6-R4**：现场验收问题必须提供复现包：环境、数据版本、算法版本、批次/轨迹 ID、最小复现步骤、预期与实际。
- **验收**：数据类用例在回归集内；复现包模板可用；缺陷与质量报告字段清晰。
- **状态**：R1/R4 已实现（用例与台账）；R2/R3 为需求（未实现）。

### 5.7 Q7 在线效果指标与对客举证（有边界）

- **Q7-R1**：定义「建议被采纳」「根因判断正确」的判定规则与反例，明确采样框、去重规则、归因窗口与最小样本。
- **Q7-R2**：统计必须给出比率与 95% 置信区间，并声明不可外推范围与选择偏差。
- **Q7-R3**：数据源缺失时输出「不可测」，禁止用估计值、经验值或人工编造数字充当指标。
- **验收**（数据源就绪后）：反馈入口、抽样脚本、口径文档与月度报告齐备，抽查样本可回溯。
- **状态**：**需求（未实现）**；当前无采纳/根因反馈入口，只能人工抽样与台账记录。

### 5.8 Q8 记忆与经验治理（P2 设计需求）

- **Q8-R1**：Agent 结论回流入库前必须过门控：来源可追溯、证据充分、不与现有规则冲突；不满足则拒绝入库并记录原因。
- **Q8-R2**：经验条目状态机 `draft → candidate → effective → retired`，晋级需样本量阈值 + 人工确认双条件，退役保留历史。
- **Q8-R3**：定期回标只追加新版本，不改写历史条目；回标结论需可审计。
- **验收**：状态迁移有审计记录；回标历史可查；生效条目可追溯到证据与确认人。
- **状态**：记忆存储已具备（事实/规则）；门控、回标、晋级为**需求（未实现）**。

## 6. 发版质量门禁矩阵

| 层 | 检查内容 | 触发时机 | 命令/接口 | 阻塞 | 产出举证 |
| --- | --- | --- | --- | --- | --- |
| L0 仓库与规范 | 敏感信息、目录登记、大文件、提交规范 | 每次推送 | `make check-repository`、`make check-commits` | 是 | CI 日志 |
| L1 语法与前端构建 | Python 编译、ESLint/Prettier、TypeScript 与生产构建 | 每次推送 | `make check`、`make lint-web check-format build-web` | 是 | CI 日志、`web/dist` |
| L2 离线回归 | 权限、流程、开发门禁、评估单元测试 | 每次推送 | `make test` | 是 | 测试报告 |
| L3 合成轨迹回放 | Agent 判定与报告（离线合成） | 每次推送 | `make evals-agent-replay` | 是 | 评测报告 JSON |
| L4 在线场景评测 | RAG 三层 / Agent 真实批次，与基线对比 | 发布前，受控触发 | `POST /api/evaluations/runs/trigger`、`make evals-center-publish` | 是（发布前） | 评测批次 + 原始报告对象（SHA-256） |
| L5 发布后观测 | 在线效果指标、失败归因、缺陷闭环 | 发布后周期 | 受控抽样与台账（数据源就绪后接入） | 否（观察项，触发阈值后升级） | 观测报告（P1/P2） |

门禁结论必须记录「层级、批次编号、数据集版本、算法版本、通过/失败、时间与执行人」，作为验收材料的一部分。

## 7. 证据包与决策轨迹

| 字段 | 来源 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dataset_version` | `eval_datasets.version` | 是 | 数据集版本，内容变更必须升版本 |
| `algorithm_version` | `eval_profiles.version_tag`/`digest` | 是 | 算法版本快照（见第 8 节） |
| `git_sha` | 批次/运行时快照 | 是 | 代码提交 |
| `mode` / `scope` | `eval_runs` | 是 | 执行方式与覆盖范围 |
| `stop_reason` | 运行期停止判定 | 是 | 完成/取消/超时/轮次上限/证据不足/越权拦截 |
| `rule_results` | 判定与核验 | 是 | 约束、引用、数字核验结果 |
| `citations` | 发布结果 | 按需 | 引用文档、版本与片段 |
| `human_confirmations` | `task_reviews`/`approvals` | 按需 | 审核人、结论、时间 |
| `trace_id` / `run_id` | 轨迹与评测批次 | 是 | 可回放定位 |
| `report_sha256` | 原始报告对象 | 是 | 完整性校验 |

存储位置：元数据与逐例在 PostgreSQL（`eval_runs`、`eval_case_results`、`eval_baselines`），原始报告在对象存储（`eval_run_reports` 记录对象键与 SHA-256，MinIO 不可用时回退本地私有目录），轨迹在任务 Span 与诊断事件，写入审计在 `audit_events` 与 `eval_audit_logs`。

**导出要求（P1 需求）**：按批次生成验收证据包（JSON + 摘要），字段来自上述来源，生成后计算 SHA-256 并可校验；导出过程不修改原始数据。

## 8. 模型通道与算法版本口径（本次更新）

| 项 | 口径 |
| --- | --- |
| 首选通道 | 阿里云百炼（`BAILIAN_*`，OpenAI 兼容，DeepSeek V4.1 Flash），用于首次 API 调用 |
| 故障转移顺序 | 百炼 → 商汤海外版 → Dots → 商汤国内主 Key → 商汤国内备用 Key；未配置密钥的通道自动跳过 |
| 算法版本摘要 | `git_sha` + 模型标识 + 检索参数 + Prompt 源文件 SHA-256 + 判定器 SHA-256，同一摘要复用同一算法版本 |
| 可比条件 | 数据集版本、`scope`、`mode`、判定器版本一致；历史 V0 legacy 数据集与 V1 不可比 |
| 变更影响 | 通道顺序或主模型变更即产生新算法版本；V1 发布前必须用新算法版本重新建立基线，旧基线不得直接用于放行。清理旧批次用 `make evals-center-purge`（默认预演），重建基线见 [评测说明](../../evals/README.md#清理与重建基线) |

该口径与 [路由中间件](../../src/taozhi/ai/router.py)、[运行时快照](../../evals/runtime_snapshot.py) 的实现一致，变更时须同步修订本节。

## 9. 在线效果指标口径（部分采纳，边界明确）

| 指标 | 判定规则（建议） | 反例 |
| --- | --- | --- |
| 建议被采纳率 | 业务侧对建议做出可见动作（下单/发送/采纳标记）且 7 天内未撤回，计为采纳 | 仅打开不建议、动作由其他来源触发 |
| 根因判断正确率 | 人工复核确认根因与事实一致；或线上复现验证通过 | 结论碰巧正确但依据错误 |

统计要求：按业务场景分层抽样、同一对象多轮只计一次、给出比率与 95% 置信区间、公告最小样本与不可外推范围；数据源缺失时只输出「不可测」。

**当前边界**：产品暂无采纳/根因反馈入口，也没有客户侧回填数据；本指标只能作为 P2 需求定义，不能对外出具数字。
