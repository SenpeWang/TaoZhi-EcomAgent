# Agent 调研评测数据集 · 第一批评审稿

本稿为现有 10 例规划 8 个新增用例。编号 011–017 对应调研执行，018 对应调研轨迹的访问控制。用例、数字与实体均为设计样例，正式发布前需要制作夹具、复核标注并记录实测结果。

## 数据集怎样构建

从业务决策反推样本。先写清用户要据此做什么决定，再构造足以支持结论的最小证据，并写下一条看似合理却应判错的回答。例如，采购 100 件时应识别最低可成交价，同时排除起订量为 200 件的低价。这样才能区分 Agent 是否理解交易条件。

每例维护稳定 ID、版本、场景、风险、执行入口、用户输入与身份、合成工具响应或故障序列、关联证据 ID、预期行为、参考答案要点、关键错误和判定方式。参考答案允许等价表述。金额、币种、单位、数量档位、可接受的舍入误差和引用依据应逐项标注。参考答案、禁调清单和评分规则只交给判定器。Agent 通过正常入口接收任务和工具响应。

| 用途 | 收录依据 | 评审与版本 |
|---|---|---|
| 黄金集 | 业务人员精标关键事实、可接受答案与反例，另一位评审独立复核 | 保留分歧与裁决理由。修订证据或答案时提升用例版本 |
| 回归集 | 某个受支持行为在固定夹具、指定代码版本下已有通过记录 | 源自缺陷的样本应先复现旧版失败，再保存修复版通过依据。线上案例只保留合成复现 |
| 挑战集 | 有明确预期，当前版本仍失败或结果不稳定 | 单报通过数、失败步骤和能力边界。稳定通过后可纳入回归 |

“黄金”表示标注质量，“回归”和“挑战”表示验证用途。同一个黄金样本可用于回归，汇总时按唯一 ID 计数。同一故障模板及其改写共用场景族标识，整体划入开发集或保留验收集。公开仓库可用于版本回归。对外宣称泛化能力时另用受控留出集。

## 首批 8 例的验收清单

下表中的商品、页面和报价均为虚构。参数列给出影响业务结论的匹配条件，允许无关措辞变化。并行调研只校验必要的前后依赖。抓取详情页时，URL 应来自本次合成检索结果。

| 编号与用途 | 用户输入与固定证据 | 预期工具、参数或接口行为 | 参考答案要点与失败条件 |
|---|---|---|---|
| 011 黄金候选 · 阶梯价与起订量 | “只查 1688，采购 100 件 SYN-C65，每件及整单最低多少钱？” A 的 1–99 件单价 24 元，100 件起 20 元。B 单价 16 元，200 件起订。两家均未提供运费 | 必调 `search_1688_wholesale(keyword 含 SYN-C65)`，仅放行此渠道 | 选择 A，20 元/件，货款 2,000 元，运费待确认。按 B 的价格计算或混淆货款与到货总价即失败 |
| 012 黄金候选 · 跨平台同款比价 | “比较 SYN-H20 的 1688 与 Amazon 单件价格，按 1 美元兑 7 元折算。” 同款分别为 28 元与 8 美元，均为单件，费用未知 | 必调 `search_1688_wholesale(keyword)` 与 `search_amazon(query)`，两者均匹配完整型号。允许并行 | 折合 56 元，零售价与货源价相差 28 元/件。须标明汇率和口径。宣称净赚 28 元即失败 |
| 013 回归候选 · 网页口碑调研边界 | “只查 SYN-E10 用户口碑，列两条有出处的反馈。” 两个合成页面分别提及佩戴夹耳、按键易误触 | 必调 `search_web(query 含 SYN-E10)`。允许按返回 URL 调用 `fetch_web_page(url)`。禁止向 1688 或 Amazon 实际发出调用 | 两条反馈各指向对应页面。即使最终报告完全正确，只要实际调用禁用来源就失败。沿用既有 AGENT-WEB-003 的故障模式，以本夹具复跑后再纳入回归 |
| 014 黄金候选 · 合法零结果 | “在 1688 查 SYN-D40 的现货报价。” 该型号及等价查询均成功返回空列表 | `search_1688_wholesale(keyword 含 SYN-D40)` 返回 `empty`、条数为 0。只允许指定渠道 | 答复“本次未查到可核实报价”。声称商品不存在、报出单价或将空列表判为接口故障均失败 |
| 015 挑战候选 · 单侧数据源超时 | “比较 SYN-D41 在 1688 与 Amazon 的价格。” 1688 返回 36 元/件，Amazon 每次回放均超时 | 两个渠道均尝试，参数匹配 SYN-D41。保留 Amazon 的 `timeout` 和 1688 的成功状态，允许预算内重试 | 保留可核实的 36 元报价，说明海外数据源超时、价差待核实。捏造海外售价或将超时写为零条匹配即失败 |
| 016 黄金候选 · 相近型号的证据归属 | “根据网页评价确认 SYN-P8 是否支持无线充。” 摘要只列系列名，返回两份详情页。标准版明确不支持，Pro 版支持 | `search_web(query 含 SYN-P8)` 后，`fetch_web_page(url)` 至少读取标准版来源。Pro 页面可额外读取 | 答复标准版不支持并引用标准版证据。引用 Pro 页支持标准版结论，即使答案碰巧正确也失败 |
| 017 挑战候选 · 运行中更换机型 | 初始要求查询 SYN-K1 的 1688 报价，返回 19 元后用户改为“改查 SYN-K2，只报新型号”。新型号为 31 元 | 在首轮工具完成后通过运行期回调注入指令。校验后续 `search_1688_wholesale(keyword 含 SYN-K2)`，保留两次调用与指令事件的先后关系 | 最终只报价 SYN-K2、31 元，并引用新证据。复述新型号但沿用 19 元即失败 |
| 018 回归候选 · 调研轨迹权限 | 租户甲的员工 A、B 和租户乙的 C 各有一条合成调研轨迹。分别以甲的员工 A 和系统管理员发起查询 | 走鉴权后的 `/api/admin/traces` 列表、`owner_id` 筛选与详情入口 | A 默认只见本人，指定 B 被拒绝。甲的管理员选择 `all` 返回 A、B，单选 B 只返回 B。两种身份读取 C 的详情均返回 404。按响应 ID 集合和状态判定，任何越权披露单列阻断 |

## 判定、对照与归因

| 维度 | 首批指标与判定 |
|---|---|
| 任务结果 | 任务完成率 = 满足全部关键验收条件的用例数 / 适用用例数。另报关键事实命中数与应答事实数。对 014、015，恰当披露缺口属于正确交付 |
| 工具轨迹 | 必调覆盖率 = 命中的必调项 / 标注必调项。工具选择准确率 = 符合任务范围的实际调用数 / 实际调用总数。参数正确率 = 参数满足契约的调用数 / 可评判参数的调用数。另报禁调尝试、实际执行、必要依赖顺序违规和重复调用。空分母记为不适用 |
| 运行与治理 | 按场景列出输入/输出 Token、用量采集覆盖率、每例调用次数、耗时及权限结果。缺少用量记为未知。权限泄漏、调用禁用来源和无证据报价分别列出失败用例，平均分不能抵消这些失败 |

程序判定 ID、工具名、实际参数、顺序、数值、归属和可见范围。对解释是否切题、是否充分表达不确定性，给模型裁判提供合成证据、评分锚点和反例，要求返回判定依据。人工处理语义争议，按通过、失败、临界样本分层抽查。模型裁判的版本、提示词和人工一致性随运行记录，校准后再考虑用作门禁。该分工参考 DeepEval 对任务结果和工具契约的区分。[端到端评测](https://deepeval.com/docs/evaluation-end-to-end-llm-evals) · [工具正确性](https://deepeval.com/docs/metrics-tool-correctness)

离线回放先固定工具响应、超时、时钟和注入事件，记录代码提交、用例集与夹具摘要、判定器和模型版本。PR 可用合成调用记录验证判定器能分别接受正例、拒绝最小反例。真实模型在隔离环境另跑，按用例展示候选版与基线的配对结果。报告列出实际运行、失败、未运行和不可判定的数量，先发布样本数再给比率。挑战集单列。关键权限用例失败或缺测时阻止发布。

失败记录关联用例和执行步骤，显示预期、实际、证据 ID，以及最早可判定的失败点。有 Trace ID 时关联到具体模型、工具或上下文步骤。按意图与调度、模型 API、工具参数或执行、证据与答案、权限、评测采集分别归因，再记录对最终交付的影响。例如 015 的 Amazon 超时属于预设工具故障。如果报告编造海外售价，应将该用例的失败归因于答案缺乏证据。没有可用轨迹时标记采集缺失，避免误判模型。

## 线上发现与回灌

- **巡检**定时用合成身份和商品跑固定探针，检查数据源、工具与权限。**影子评测**在租户权限内对同一采样请求旁路比较候选版，只读回放获准使用的工具响应，用户仍接收当前版本结果。**A/B** 按会话稳定分桶，用户实际接收分配版本，同时比较任务完成、权限事件和 Token 消耗，预设停止条件。
- 原始流量在受控环境内排查。按失败步骤和原因聚类，选择代表样本，替换身份、商品、价格、URL 和时间，重写成最小合成夹具。业务评审确认故障仍然成立，用旧版复现并在修复版验证后，才将对应版本标为回归样本。
- Git 保存合成用例、证据、判定规则、版本清单，以及经过筛选的汇总基线。运行报告归入 `evals/reports/`，原始业务附件、生产请求正文、生产轨迹和账户标识留在受控环境中。仓库扫描器可拦截受限路径及部分凭据，发布前还需核对样本来源与业务字段。

## 当前结果如何解读

[运行器](runner.py) 已支持真实调研采集、合成执行记录重评、基线对照和分层门禁。[判定器](judges.py) 可核对声明的参数、状态、依赖顺序和参考事实引用。[执行适配器](harness.py) 在工具完成后发放运行中指令。现有 10 例仍沿用各自原有的标注范围，未标注的事实与参数不计入相关指标。CI 的固定合成用例检验判定与报告链路。上表 8 例仍待评审，018 的调研图评测与鉴权 API 验证应按各自入口执行。
