## 3. 白盒根因诊断分析（Root-Cause Analysis）

### 3.1 为什么传统黑盒评测无法发现该 Bug？
若采用传统黑盒或纯大模型打分（LLM-as-a-Judge）：
最终交付的 Markdown 研报文字优美，不仅包含了全网卖点和买家痛点，还“超额完成任务”附带了 1688 出厂价和亚马逊售价对比。黑盒裁判仅依据最终研报打分，必定会给出满分（甚至夸赞 Agent 能力全面），**从而彻底掩盖了严重的系统性越权**。

### 3.2 白盒执行轨迹定位到的代码缺陷
通过白盒链路追踪（Trace）穿透分析 `tools_called` 和状态机流转轨迹，精确定位到根因：
1. **意图路由缺陷（Over-Planning Drift）**：
   - 源码位置：`src/taozhi/orchestration/agent_system.py` 中的 `main_supervisor_node`
   - 代码分支逻辑：
     ```python
     elif not whole_f:
         next_action = "scanner_agent"
         rationale = "已掌握全网痛点，尚缺真实供应链出厂价与海外对标，主脑自主委派 scanner_agent 探查 1688 与 Amazon 双渠道。"
         new_status = "COLLECTING"
     ```
   - **根因**：Supervisor 主脑在第一轮完成 `web_agent` 的网页检索后，因状态机中的 `wholesale_findings` 仍为空，且代码缺少“根据用户初始意图边界跳过非必要模块”的强约束，导致主脑**贪婪式地继续派发** `scanner_agent`，进而调取了受限工具 `search_1688_wholesale` 和 `search_amazon`。

---

## 4. 改进措施与修复行动项（Action Items）

1. **优化 Supervisor 规划意图感知（Prompt + 路由守卫）**：
   - 在 `main_supervisor_node` 中增强用户意图分类：若用户仅要求纯舆情/行业趋势抓取（未出现“批发、出厂、比价、货源”等词），主脑自主反思大纲中将供应链比价标记为“跳过”，直接流转至终审研报；
2. **强化工具执行层契约守卫（Tool Guard）**：
   - 在子智能体调度层接入白名单校验拦截器，若当前会话或场景声明了禁用工具，严禁底层触发 API 调用；
3. **回归验证闭环**：
   - 修复后重新运行 `.venv/bin/python -m evals.agent_eval.runner --case AGENT-WEB-003`，断言 `ToolExecutionJudge` 通过，综合得分达 1.00，实现「评测—归因—修复」工程闭环。
